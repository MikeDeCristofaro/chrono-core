# Project Workflow: Chrono-Core

## Bug Tracking
All bugs, regressions, and blockers must be tracked as official **GitHub Issues** on the `chrono-core` repository.

### Issue Severity
| Level | Name | Description |
|-------|------|-------------|
| P0 | Blocker | Prevents build, breaks core loop, or stops progress entirely. |
| P1 | Critical | Major feature failure or severe visual/logic glitch. |
| P2 | High | Notable bug that should be fixed within the current sprint. |
| P3 | Normal | Minor polish or edge-case bug. |

### Issue Template
When creating an issue, please include:
1. **Description**: Clear summary of the issue.
2. **Steps to Reproduce**: Detailed list to trigger the bug.
3. **Expected Result**: What should happen.
4. **Actual Result**: What actually happened.
5. **Labels**: (e.g., `bug`, `p0`, `blocked`).
